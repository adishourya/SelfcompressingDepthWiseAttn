### Fundamentally
Fundamentally, a Layout maps from coordinate space(s) to an index space.
`(i,j,k...) -> offset `

### Algebra of layouts
CuTe also provides an “algebra of Layouts.” Layouts can be combined and manipulated to construct more complicated layouts and to tile layouts across other layouts. This can help users do things like partition layouts of data over layouts of threads.
This is very important to get coalesced read.
`
A Layout is a tuple of (Shape, Stride). Semantically, it implements a mapping
from any coordinate within the Shape to an index via the Stride.
Layout : (shape) : (stride)
shape : (m,n,l)
stride : (a,b,c)
`

### shape dot stride to get offset
inedex to offset calculation is given by: shape dot stride
`i.e A : (3,4,5) : (1,3,12)
A[0,1,2] = A[0*1 + 1*3 + 2*12] = A[27]
`
A Layout can be composed with data – e.g., a pointer or an array – to create a Tensor. The index generated by the Layout is used to subscript an iterator to retrieve the appropriate data. For details on Tensor, please refer to the Tensor section of the tutorial.

#--------------- Layout Concepts
L_a is said to be compatible with L_b
iff shape(L_a) is compatible with shape(L_b)
conditions for compatibility:
  1. size of shape of L_a == size of shape of L_b
  2. all coordinates within L_a are also valid within L_b

examples of compatible layout:
shape 24 is *not* compatible with shape 32
shape 24 is compatible with shape(4,6)
shape(4,6) is compatible with shape ((2,2),6).... i.e with modes expanded to multi-modes
shape(4,6) is compatible with shape ((2,2),(2,3))
shape ((2,3),4) is *not* compatible with shape ((2,2),(3,2))
shape(24) is *not* compatible with shape 24

That is, compatible is a weak partial order on Shapes as it is reflexive, antisymmetric, and transitive

## Layout Coordintes
mapping between sets of coordintes happens via a colexicographical order
that is reading right to left. instead of lexicographical which reads left to right

>  A layout can be addressed using multiple coordinate systems, and CuTe uses a
consistent way (colexicographical order) to convert between them.

i.e a layout of shape (3,(2,3))
can have a cordinate input of 1d 0-17, or 2d (:3,:6) or h-d (:3,(:2,:3))

```py
def example_cordinate_mapping():
    # say we have a shape of (3,(2,3))
    d0, d1 , d2 = 3,2,3
    # then what would be the 1d cordinate of it.
    # this is just 1d cordinate not the offset.
    # stride is not used in calculating cordinate mapping.

    # here the range is 3,6 -> 18
    def mapping(one_d):
        i = one_d % d0
        one_d = one_d // d0 # drop component
        j = one_d % d1
        one_d = one_d // d1 # drop component.
        k = one_d
        return i,j,k
        
    for i in range(18):
        print(f"one_d = {i} natural = {mapping(i)}")
  # this returns the same output as the documentation.
```
index mapping
index_mapping or the offset mapping is given by the dot product of the natural index with the stride.

R(c) := (A o B)(c) := A(B(c))

## Computing Composition
let A = s_a : m_a [s : shape , m : stride]
let B = s_b : m_b

Trivial Case
 when A and B are flattened (is integreal)
Then R = AoB = s_b : (m_a * m_d)
The left distributivity will get clear when we deal with matrices
```py
@cute.jit
def example_composition_layout2():
    A = cute.make_layout(shape=(20,), stride=(10,))
    B = cute.make_layout(shape=(4),stride=(4))
    AoB = cute.composition(A,B)
    cute.printf(AoB)

AoB --> 4 : 40
```

But when A is multimodal we need to be more careful.
Case2 : When B is integral
we want:
1) “remove” the first m_b elements from A
2) “keep” the first s_b of those strided elements.
```py
def example_composition_layout2():
    A = cute.make_layout(shape=(3,6,2,8), stride=(1,3,18,36))
    B = cute.make_layout(shape=(16,),stride=(9,))
    AoB = cute.composition(A,B)
    cute.printf(AoB)
AoB --> 16 : 9
```
Lets walk through the example now:
1. Removing the first m_b elements of A
can be computed by progressively “dividing
out” the first m_b elements from the shape of A s_a
starting from the left (first mode).
> (3,6,2,8) / 9 = (3, (3 *2) , 2 , 8) /9 = (1 , 2 , 2 ,8)
Keep track of the factors with the mode that got divided here the first 2 modes were divided by 3

obviously this division can only work for certain shapes of s_a and certain strides for m_b.

2. keep the first s_b elements of the strided A.
This can be done by modding out the first m_b elements
strating from the left (first mode).
(1,2,2,8) % 16
product scan : (1 , 2, 4 , 32) we need a shape which results the scan of (1,2,4,16)
shape = (1,2,2,4)
stride = (3*w1, 3*w2 , w3 ,w4) : the modes that were factored out

so the composed layout is (1,2,2,4) : (3*w1, 3*w2 , w3 , w4)
> unfortunately now it returns coalesced results.. so we cant see it

Semantically this means interpret the layout 20 : 20 as a row major 5,4 matrix
steps :
1. (20 : 50) o (5,4 : 4,1)  
2. concatination of sublayouts i.e (5,4 o 4,1) = [5:4 , 4:1]
(20 : 50) o (5:4 , 4:1)
3. Left Distributivity
(20:50 o 5:4) Trivial case (integral) => 5 : (50 * 4)
(20:50 o 4:1) Trivial case (integral) => 4 : (50 * 1)
4. unconcatinate
[5:200 , 4:50] => 5,4 : 200,50

## complement
- Also the best definition for composition
Before getting to “product” and “divide,” we need one more operation.

- We can think of composition as a layout B that is “selecting” certain
coordinates from another layout A.

complement idea:
- But what about the coordinates that aren’t “selected”? To
implement generic tiling, we want to be able to select arbitrary elements – the
tile – and to describe the layout of those tiles – the leftovers, or the “rest.”

The complement returns the rest. it takes a layout and a shape as input arg.
the shape is also called as co-target here.

The cotarget parameter above is most commonly an integer. 
Examples:
1. Complement(4:1 , 24)
> 6 : 4
step1 : find a layout which has the co-sizze of 24 that also produces the input
layout when de-concatinated
(4,6) : 1,4 => [4:1, 6:4]
the layout 4:1 is effectively repeated (concatinated) 6 times with 6:4 on the second mode.

2. Complement(6:4, 24)
> 4 : 1
similar concat idea. 4,6 : 1,4 has a co-size of 24
=>[4:1 , 6:4]
returns 4:1 

3. Complement((4,6):(1,4), 24)
already has cosize of 24. nothing needs to be concatinated.
> 1 : 0 which is just 0

4. Complement(4:2 , 24)
note we can no longer make simpleton 6,4 layouts as something like
6,4 : 1,2 is not valid.
6,4 : 1,4 does not produce 4 : 2 in de-concatination
6,4 : 12,2 has a co-size of 66 > 24
 Layout: shape=(6, 4), stride=(12, 2)

imagine a layout 4,(2,3) : 2, (1,8) has a co-size of 24

  so the layout can be de-concatinated as [4:2 , 2,3:1:8]

  5. Complement((2,4):(1,6) , 24)
  that is : Layout: shape=(2, 4), stride=(1, 6)

## Tiling or Division

- Finally, we can define the division of a Layout by another Layout. Functions
that divide a layout into components are useful as a basis for tiling and
partitioning layouts.

- In this section, we’ll define logical_divide(Layout, Layout),
which again considers all Layouts as 1-D functions from integers to integers,
and then use that definition to create multidimensional Layout divides.

- Informally, logical_divide(A, B) splits a layout A into two modes
in the first mode are all elements pointed to by B ;; which just means composition AoB
and in the second mode are all elements not pointed to by B ;; which means complement of B. B`

The Division operation in CuTe is used to split a layout into tiles, which is
particularly useful for partitioning data across threads or memory hierarchies.

Logical divide : When applied to two Layouts, logical_divide splits a layout
into two modes -- the first mode contains the elements pointed to by the tiler,
and the second mode contains the remaining elements.
